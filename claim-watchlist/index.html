What this actually is, and its real limits

Stated honestly, same discipline as every other tool on this site:

  • CPSC (SaferProducts.gov): a real 2023 investigation found this database can undercount real complaint volume heavily -- a useful leading indicator, not a complete one.
  • openFDA MAUDE: restricted to Death-only reports to avoid the real "denominator problem" (high-volume device categories like insulin pumps generate hundreds of thousands of routine malfunction reports/year). FDA itself disclaims this data for rate/trend comparison, and the same death can be double-reported by both a manufacturer and a facility.
  • NHTSA ODI: not yet normalized by registered-fleet size -- the rawest version of this feed is dominated by simply the best-selling vehicles, not necessarily genuine emerging defects. Disclosed, not hidden.
  • A match is a real, currently-tracked federal complaint-velocity cluster, not a legal finding that this specific claim is part of it.
  • This checks a named manufacturer/model you already have in hand. To instead watch a whole product category (e.g. "lithium battery", "hoverboard") for a real CPSC recall rate that's accelerating, see the CPSC Recall Velocity feed.

Also available as an API

The exact same logic, callable from a claims system or bordereau pipeline. Batch mode checks up to 500 open claims in one call. Honest status: a working, tested local API, not yet deployed to a public URL.

curl -X POST https://<your-deployment>/v1/claim-watchlist-check \
  -H "Content-Type: application/json" \
  -d '{"manufacturer": "Zuru Inc.", "model_or_identifier": "Size 4"}'
